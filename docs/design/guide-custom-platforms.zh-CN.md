# 自定义平台开发指导说明（guide-custom-platforms）

> 目的：给"第一次写 AgentLRay 自定义平台适配器"的开发者一份**流程化上手指导**——从决策到验证的完整步骤、契约要点与常见坑。本文不重复贴完整样例代码，需要可运行的最小适配器全文请直接对照 [`custom-platform-example.zh-CN.md`](custom-platform-example.zh-CN.md)（P6 实测产物，含完整扁平 JSONL 样例 + 全部真实命令输出）。
> 设计依据：[`design-custom-platforms.zh-CN.md`](design-custom-platforms.zh-CN.md)（Q1–Q12 决策）+ [`adr-0001-custom-platform-adapter.zh-CN.md`](adr-0001-custom-platform-adapter.zh-CN.md)。本文件全部契约与命令行为**已对照落地代码核对**（`lib/platforms/loader.js`、`lib/platforms/index.js`、`bin/platform.js`、`bin/sessions.js`、`lib/cli-bins.js`），非示意。

> 📌 **v2 改动说明（2026-11-07，平台来源统一与全表面等价）**：下文基于 v1 编写，v2 相对 v1 有这些实质变化，阅读时以本文「§0.1 v2 契约与能力」为准：
> 1. **来源三目录 + 启停/替代开关**：包内置 `lib/platforms/builtin/`、项目 `<repo>/platforms/`（随包分发）、用户 `~/.agentlray/platforms/` 三者同一加载器。新增 `agentlray platform mount/unmount/replace/unreplace/export` 子命令与 `PUT/DELETE /api/platforms/:id/mount|replace`；**per-platform 启停现已支持**（v1「无开关」过时）。
> 2. **parse 可为 null**（SQLite 平台如 hermes 兼容）；`defaultDir / label / id / getSession` 为必需，`parse` 放宽。
> 3. **inspect 离线诊断现为 opt-in 能力位**（v1「仅内置」过时）：适配器声明 `inspect` hook 即接入。
> 4. **全表面 hook 大幅扩展**：会话列表/详情/agents/children/spawn、search/insights/prompts/tool-audit/OTLP 全部可经 hook 由自定义平台接入；core 不再对内置平台 id 特判。
> 5. **薄适配器 + `AGENTLRAY_PKG_ROOT`**：`platform export <id>` 生成薄适配器（包根解析），包升级自动跟随。
> 6. **同 id 覆盖**：项目/用户同名仅当该 id 已声明 `replaced` 才覆盖包内置，否则 broken（需先 `platform export/replace <id>`）。

## 0.1 v2 契约与能力（先读这篇）

### 身份 / 目录 / UI 元数据

| 字段 | 说明 |
| --- | --- |
| `id` | `^[a-z0-9][a-z0-9-]*$`，catalog 键 |
| `label` | 展示名 |
| `defaultDir()` | 会话根目录 |
| `dirSettingKey?` | 设置面板持久化键（如 `codexDir`）；空则不提供目录配置 |
| `dirSettingLabel?` / `dirSettingHint?` | 设置面板标签 / 提示 |
| `dirParam?` | 聚合/搜索/洞察请求的 query 参数名（如 `dirClaude`）；空则只支持单 `?dir=` |
| `color?` | 前端平台标识色 |
| `needsAgent?` | openclaw 式按 agent 维度组织 |
| `bin?` / `version?` | CLI 默认可执行名（null 表示无）/ 契约版本 |

### 会话 / 子代理 / spawn hooks

| hook | 签名 | 触发表面 |
| --- | --- | --- |
| `list?` | `(dir) => summary[]` | 平台全部会话（非 agent 维度） |
| `listForAgent?` | `(dir, agent, includeArchived)` | 单 agent 会话（`needsAgent`） |
| `listAllAgents?` | `(dir, opts) => summary[]` | 跨全部 agents 合并（`needsAgent`） |
| `listAgents?` | `(dir) => string[]` | agent 列表（agent 选择器） |
| `find?` | `(dir, sid, opts?) => path\|null` | watch / OTLP |
| `parse?` | `(file) => { session, messages }` | 文件归一化（可 null） |
| `getSession?` | `(dir, sid, opts?) => payload\|null` | 详情（agent 平台用 `opts.agent`） |
| `getSessionAcrossAgents?` | `(dir, sid) => payload\|null` | 跨 agent 详情（`needsAgent`） |
| `collectFiles?` | `(dir, opts?) => [{path,file,sessionId,agent?}]` | search / prompts / audit 批量扫描 |
| `watchParse?` | `(rec, line?) => {messages?,session?}\|null` | SSE 实时尾随 |
| `watch?` | `(req, res, ctx) => void` | 非文件平台完整 SSE（hermes） |
| `listChildren?` / `getChild?` | `(dir, sid)` / `(dir, sid, name)` | 子代理列表 / 详情 |
| `spawnMap?` / `spawnTree?` | `(dir)` | spawn 关系图 / 树 |

### 分析 / 导出 / inspect hooks

| hook | 说明 |
| --- | --- |
| `search?` | 整平台搜索（存在时优先于通用文件扫描） |
| `searchFile?` | 单文件搜索器；缺省用通用 JSONL 搜索 |
| `searchSupplement?` | 额外来源（如 claude-code 的 history.jsonl 兜底） |
| `computeInsights?` / `insightsScanFile?` | 整平台 / 单文件分析；缺省通用扫描 |
| `extractPrompts?` / `extractPromptsFromFile?` | 整平台 / 单文件 prompt 提取；缺省通用 JSONL 提取器 |
| `computeToolAudit?` / `scanToolAuditFile?` | 整平台 / 单文件工具审计 |
| `otlpSession?` | OTLP 导出优先；缺省走 `find+parse`（且 `!needsAgent`） |
| `inspect?` | `{ normalizeRecord, rawToolEntries, adapterFiles }` 离线 inspect（opt-in） |
| `resume?` / `create?` / `resumeHooks?` | CLI 续跑 / 新建 / 续跑前后治理 |

> 所有 hook **均可选**；缺位则对应能力位为 false，UI/接口自动缺位，不报错。内置 adapter 是各能力的最佳样例（`lib/platforms/builtin/*.js`）。

### 薄适配器与 `AGENTLRAY_PKG_ROOT`

`agentlray platform export <id> --out <dir>` 生成薄适配器（§6.5 模板）：

```js
'use strict';
// Generated by `agentlray platform export codex`. Load through AgentLRay.
const path = require('path');
const root = process.env.AGENTLRAY_PKG_ROOT;
if (!root) throw new Error('AGENTLRAY_PKG_ROOT is not set; load this adapter through AgentLRay.');
module.exports = require(path.join(root, 'lib/platforms/builtin/codex.js'));
```

- 默认把 id 写入 `settings.replaced`、移出 `settings.disabled`；重启后生效。
- 包升级自动跟随新实现（薄适配器语义）；如需自定义可在 `--out` 后编辑成独立实现（但要手动把 id 从 `replaced` 移除以免 strict 顶包）。
- 项目/用户适配器做薄包装时同样通过 `AGENTLRAY_PKG_ROOT` 解析包内路径，勿用相对路径。
- 同 id 覆盖：项目/用户同名仅当 `settings.replaced ∪ manifest.replaces` 声明了该 id 才允许覆盖包内置，否则 broken（错误提示「先 export/replace」）。



## 0. 一句话定位

接入一个不在内置 7 平台（openclaw / codex / claude-code / hermes / omp / dsh / gemini）里的新平台，**不改 AgentLRay 源码**：写一个 CommonJS 平台适配器放进 `~/.agentlray/platforms/`，启动时加载器校验通过即并入注册表，会话列表 / 详情 / 搜索 / prompts / 工具体检 / SSE watch / 导出 / CLI `sessions` 等 generic 表面按**能力位**自动接入。**inspect 离线诊断与 resume 都按适配器能力位 opt-in：内置 omp / codex / claude-code 声明 `inspect` hook（自定义适配器同样可声明 `inspect`（`normalize` + `rawToolEntries`）接入 `inspect` / `evidence`，如 `co-mind`）；resume 由内置 codex / claude-code / omp / gemini / hermes 与声明 `resume` 的自定义适配器提供，openclaw 与 dsh 无原生续跑。**

## 1. 开发流程（5 步）

### 1.1 写适配器文件

- 文件：`*.js`，CommonJS，`module.exports = <adapter>`；单文件单适配器；文件名即无序，加载按字母序。
- 依赖约束：**仅 Node 内置模块 + `@agentlray/shared/*` 共享层**（如 `@agentlray/shared/helpers` 的 `withMetadataCache / makeMessage / fileBasedGetSession / sortSessionsByTimestampDesc / topToolsOf / captureLastMessage`、`@agentlray/shared/tail-state`、`@agentlray/shared/status`；裸名由 `lib/platforms/shared-alias.js` 全局注册并解析到 `lib/platforms/shared/`），零第三方依赖（保证无安装、无版本冲突）。
- 必需字段（加载器校验，违反 → 该文件 marked broken）：

| 字段 | 签名 | 说明 |
| --- | --- | --- |
| `id` | `string` | 正则 `^[a-z0-9][a-z0-9-]*$`；与内置/先前自定义冲突 → broken（`id 已被占用：<id>`），绝不覆盖 |
| `label` | `string` | 人类可读名 |
| `defaultDir()` | `() => string` | 会话根目录；适配器内可读自身 env；通用 `?dir=`/`--dir` 覆盖天然生效 |
| `parse(file)` | `async (filePath) => { session, messages }` | 归一化带 `session` + `messages`；消息复用统一形状，不自造造型 |
| `getSession(dir, id)` | `async (dir, sid) => { session, messages } \| null` | 详情按 id；文件型可用 `fileBasedGetSession(find, parse)` |

> **`list(dir)` 是"推荐但加载器不强制"**（可为 `null`，同 openclaw.list 语义；缺它不参与列表类 surface 但加载不失败）。但 **`agentlray platform validate` 会要求 `list` 存在**（枚举会话计数）。摘要形状**至少含 `id / timestamp / lastActivity / mtimeMs`**（状态推导依赖）；建议带 `cwd / messageCount / tail / firstUserMessage`。`tail` 是精确四态判定证据（无 tail 时 `deriveStatus` 退化为时间窗判定，更粗糙——推荐用 `@agentlray/shared/tail-state`（`createTailState → finishTail`）/ `lib/status.js` 维护）。

- 可选能力位（缺谁谁缺位、不报错）：

| 字段 | 触发表面 |
| --- | --- |
| `find(dir, sid, opts?)` | `watch`（与 `watchParse` 一起）、`OTLP`（与 `parse` 一起） |
| `collectFiles(dir, opts?)` | `search` / `prompts` / `tool-audit` 批量扫描 |
| `watchParse(rec, line?)` | SSE 实时尾随（与 `find` 一起；缺位时 `/api/watch` → `400 {"error":"平台不支持实时尾随"}`） |
| `needsAgent` | openclaw 式按 agent 平台（置 true → 详情/列表需 `agent`、不进入 OTLP） |
| `resume` | CLI `sessions resume`（见 1.4） |
| `version` | 契约版本（v1 起始） |

### 1.2 放入并启用

- 投递到 `~/.agentlray/platforms/`（来源三目录：包内置 / `<repo>/platforms/` 项目 / `~/.agentlray/platforms/` 用户）；默认挂载，**可用 `agentlray platform unmount <id>` 停用、`mount <id>` 重新挂载**（v2 起支持 per-platform 开关），卸载也可删/移走文件。
- 语义：加载按字母序；单文件 try/catch 隔离（坏文件不打断启动、不影响其余）；id 冲突记 broken 不覆盖；`AGENTLRAY_NO_PLUGINS=1` 全局逃生（跳过项目+用户来源，`platform list` 显示逃生 broken 说明）。
- **重启服务 / 重新跑 CLI 生效**——加载发生在进程启动的模块 require 期（`lib/platforms/index.js` 末尾同步并入 `PLATFORMS`，下游派生点都在 require 期同步读取）。

### 1.3 验证

```bash
agentlray platform validate ~/.agentlray/platforms/<file>.js --json   # 干式校验 + 枚举会话
agentlray platform list                                                # 内置 + 自定义 + broken 总览
```

- `validate` 与加载器共用同一套校验（同一 `validateAdapter`，不复制逻辑）：导出对象 → `id` 正则 → 必需函数 `defaultDir / parse / getSession` → `label` 字符串 → id 不冲突。通过后再调真实 `list(defaultDir())` 报 `sessionCount` 与 `firstId`。**dry-run，不写注册表**。
- 输出约定：`--json` 成功 `{schemaVersion:1, kind:"platform-validate", ok:true, platform:{id,label}, sessionCount, firstId, note}`；`list --json` 为 `{schemaVersion:1, kind:"platforms", platforms:[…]}`（顺序内置 → 自定义 → broken）。错误一律 `{schemaVersion:1, kind:"error", error:{code,message}}`，退出码 1；错误三型：`usage`（参数）/ `validate`（校验失败）/ `validate-sessions`（校验通过但 `defaultDir` 抛出 / 缺 `list` / `list` 抛错 / 非数组）。
- stderr 附信任提示：「平台适配器会以你的用户权限执行其任意代码：只投递可信的适配器文件」。

### 1.4 接 resume（可选，opt-in）

```js
module.exports.resume = {
  bin: 'flat-cli',                               // 默认命令名
  args: (sessionId, opts) => ['--resume', sessionId],
};
```

- 实际可执行名由 `resolveCliBin()` 解析：**环境变量 `AGENTLRAY_<ID>_BIN` > `~/.agentlray/settings.json` 的 `cliBins` section 的 `<id>` 键 > `bin` 默认名**（env 名推导：平台 id 非字母数字 → `_` 后大写，如 `my-copilot` → `AGENTLRAY_MY_COPILOT_BIN`）。
- 未声明 → `sessions resume` 报错（`code:"usage"`，文案 "Platform '<id>' has no native resume command. Only <已挂载且声明 resume 的平台名单>, or custom platforms declaring resume, are supported."；名单由 `bin/sessions.js` 的 `RESUME_PLATFORMS` 在 require 期从注册表动态收敛，不再是模块级 `RESUME_BINS` 表）。内置 codex / claude-code / omp / gemini / hermes 在各自适配器里声明 `resume`；openclaw 与 dsh 无原生续跑。
- 实测（声明 resume 后，`--json` 未加 `--run`）：`{"schemaVersion":1,"kind":"resume","platform":"flat-logs","id":"a","cwd":...,"bin":"flat-cli","args":["--resume","a"],"command":"cd ... && flat-cli --resume a",...}`；加 `--run` 才 spawn 并透传 stdin/stdout 与退出码。

### 1.5 观察前端与全量行为

- 自定义平台出现在平台栏（React 前端服务端驱动展示）；broken 平台带 ⚠ 徽标（悬停 title 显示 error）、不参与会话查询、无启停交互。
- 能力缺位自动缺位：无 `collectFiles` → search/prompts/audit 正常返回不报错；无 `watchParse` → `/api/watch` 400；`PUT /api/settings` 的 `ui` section 白名单按注册表自动收自定义 id。
- 状态推导平台中立：`list` 摘要形状符合即自动获得四态分组与排序，无需改状态逻辑。

## 2. 硬性边界（不做的事）

| 项 | 说明 |
| --- | --- |
| 网络 / 沙箱 / 签名 | 不新增；适配器=用户全权限代码，等同手动执行，文档与 validate 输出均明示 |
| per-platform 启停 | v2 起支持：`platform mount/unmount` / `PUT–DELETE /api/platforms/:id/mount`；文件存在只是默认挂载 |
| inspect 离线诊断 | omp/codex/claude-code 内置；自定义可 opt-in 声明 `inspect` hook 接入 |
| 第三方依赖 | 禁止（只内置 + `@agentlray/shared/*`） |
| resume 默认支持 | 内置 codex / claude-code / omp / gemini / hermes 声明；openclaw / dsh 无原生续跑；自定义需 opt-in 声明 `resume` |

## 3. 开发对照清单（checklist）

- [ ] `id` 符合 `^[a-z0-9][a-z0-9-]*$` 且不与内置/其它自定义冲突
- [ ] 必需函数 `defaultDir / parse / getSession` 存在；`label` 为字符串
- [ ] `list` 摘要含 `id / timestamp / lastActivity / mtimeMs`（推荐含 `tail`）
- [ ] `parse` 消息复用统一形状（不自造造型）；零第三方依赖
- [ ] 只投递可信代码；必要时 `AGENTLRAY_NO_PLUGINS=1` 逃生
- [ ] `agentlray platform validate <file> --json` 通过（`ok:true` + 会话计数）
- [ ] 重启后 `agentlray platform list` 可见自定义（及 broken 原因）
- [ ] URI 兜底走 `/api/:platform/sessions[?agent=]` 与 `/api/:platform/sessions/:id`（前端已自动）
- [ ] resume（若需）已声明 `{ bin, args }` 并实测 `sessions resume` 命令生成 / `--run` spawn
