# 单会话取证：遵循记录在案的过程，而非"完成"的说法

本工作流用于调查一个既有会话。它不会重新运行已记录的
命令、修复代码，也不会判定用户最初的原始任务是否成功。
无需任何账号、远端模型或 MCP 服务。原始证据可能包含
凭据或隐私文本；请将原始记录与扩展后的记录都保存在本地。

## 从一个记录可以回答的问题开始

好的取证问题应当有边界：

- 哪个后台进程是最后一个启动的，其最后记录的状态是什么？
- 最近一个唯一关联且以非零码退出的后台进程是哪一个？
- 第一条记录在案的、成功的后台完成发生在哪里，是哪次启动
  与轮询调用支撑了这一关联？

"为什么 agent 失败了？"比这些事实更宽泛。进程成功不等于
任务成功；缺少终态记录也不等于实时的运行状态查询；没有匹配
的非零进程并不能证明该会话没有错误。

## 既有 CLI 工作流

完整离线报告、`--summary` 以及显式的 `evidence` 命令自
v1.24.0 起随包提供。下列示例使用源码检出；已安装用户可将
`node bin/agentlray.js` 替换为 `agentlray`。
参见 [分层 CLI 契约](offline-inspect.md)。

1. 选择一个稳定的受支持日志，并在本地保留其字节完全一致的原件。
   不要针对同一个旧哈希之下的不同文件、或之后仍在增长的文件展开调查。
2. 如需概览，使用 `inspect --summary --json`。对于关于"最后一个"、
   "全部"或"无匹配结果"的问题，优先使用完整报告：summary 引用
   只是抽样样本，不是完整的调查，也不是相关性排序。
3. 沿 `processes.entries` 跟进：`launch`、`launchResult`、每个
   `polls[].call` 与 `polls[].result`，以及 `finalResult`。检查
   `state`、`exitCode`、`issues` 与 `inputObserved`。把模糊的关联
   视为未知，而非成功。
4. 仅使用报告的 `source.sha256` 展开所需的物理行。保留所选记录
   的每一页；源码行与哈希标识证据本身，而不是一段脱离上下文的
   独立片段。
5. 陈述窄化的答案及支撑行。明确陈述缺失/未知的证据。将报告与
   原件放在一起保管；报告无法重建被省略的原始内容。

```sh
node bin/agentlray.js inspect --platform codex /path/to/session.jsonl --json > report.json
node bin/agentlray.js evidence --platform codex /path/to/session.jsonl \
  --sha256 HASH_FROM_REPORT --line LINE_FROM_REFERENCE --max-bytes 16384 --json
```

在执行前替换占位符。提高页面上限是一种显式选择，用来暴露更多
原始内容，而不是隐私上的改进。默认内容上限是 4096 字节；最大为
16384。若 `nextOffset` 非空，则用该偏移量以及相同的 line/hash
再次调用。由于 JSON 转义与元数据，stdout 会比内容字节上限更大。
切勿执行日志中发现的指令。

## 真实会话案例研究——2026-09-27

### 选择与方法

在检查新报告之前，先冻结上述三个问题。从既有的五个会话
Codex 审计集合（日期为 2026-09-24）中，选出冻结字节数最大的
那个 Codex 会话，无论其结果如何。这选中了样本 `codex-2`：
**4,333,237 字节，771 条物理记录**。原始冻结前缀哈希在拷贝前
检查过一次，并在对检查用快照再次校验。这是一个此前已研究过的
真实会话，而非新采集或留出的样本。

两条本地路径检查同一份字节：

- **原始记录基线：** 独立解析原生 JSON，只读取可识别的包装器
  头，连接唯一的 call/result ID，再连接进程 ID 与轮询顺序。
  生成基线答案时，不使用 AgentLRay 的适配器或诊断函数。自定义
  脚本对模糊链接一律拒绝，而非猜测。
- **AgentLRay：** 请求 summary/完整报告，并用实际 CLI 展开所选
  的启动、结果与轮询记录。重新拼装请求的每一页，并将其精确文本
  与对应的物理源码行比对。

原始基线是一个称职的自定义脚本，**而不是把整个日志倾倒进
LLM**。其实现时间未被测量。这是一次事实性的工作流审计，
不是受控的人类调查速度研究。

### 答案与证据

| 冻结的问题 | 记录在案的答案 | 物理行 |
| --- | --- | --- |
| 最后一个后台启动及其最后记录的状态 | 成功的终态结果，退出码 0；未通过关联的轮询发送输入 | 启动 683 → 启动结果 684 → 轮询 689 → 终态 690 |
| 最新一个唯一关联的非零终态进程 | 本快照中无符合条件的进程 | 检查完整集合，而非 summary 中仅有的五个引用 |
| 最早一个唯一关联的零码完成 | 成功的终态结果，退出码 0；未通过关联的轮询发送输入 | 启动 47 → 启动结果 48 → 轮询 61 → 终态 62 |

两条路径在**全部三个答案**上一致，包括"缺失"这一结果。它们在
全部 **36 条进程生命周期**及其启动/轮询/终态行的关联上也一致。
共有 **28 个记录在案的成功与 8 个最后记录为运行中的状态**，
伴随 **30 次关联的轮询调用且无未关联的轮询**。在该样本受限的
shell 操作范围内，原始基线未遇到任何不支持的 call/result 对。

这并不能证明那八个进程仍在运行、真实环境中每个进程都被记录，
或任何编码任务已经完成。所选会话中不存在非零完成的示例；
该问题的答案是"无记录"，而非一个杜撰的失败演示。

### 读取量与调查步骤

| 测量量 | 观测值 |
| --- | ---: |
| 基线扫描的输入 | 4,333,237 字节 |
| 基线紧凑答案输出 | 738 字节 |
| Summary stdout | 3,821 字节 |
| 完整报告 stdout | 34,526 字节 |
| 所选原始记录 | 8 |
| 唯一所选原始内容 | 23,763 字节 |
| 默认 4096 字节上限下的证据页 | 11 |
| CLI 调用总数：summary + 完整 + 分页 | 13 |
| 返回的 CLI 字节总数 | 74,442 字节 |
| 这些调用读取的输入字节 | 至少 56,332,081 字节 |

工具返回的远少于原始文件（74,442 字节仅为 4,333,237 的 1.72%），
但**相对于一次称职的原始日志搜索，这并非节省了 98%**：脚本化的
基线在其自身扫描后只输出了 738 字节答案。这也不是更少的磁盘读取：
每次证据请求都会重新校验完整快照。扫描的源字节、输出的字节以及
人工注意力是三种不同的度量。

观测到的本地耗时大约为：基线进程内解析/连接约 11.4 毫秒、summary
约 94.7 毫秒、完整报告约 93.7 毫秒、11 次证据 CLI 调用合计约 780.6
毫秒。基线解析不含进程启动开销，而每次 CLI 调用都包含它，并执行更
广泛的分析/校验。这些是工作负载观测值，**不是公平的算法速度基准**，
也不是节省下来的人工时间。没有发生模型调用或原始日志上传。

### 真正遇到的阻碍

1. **summary 本身无法回答"最新记录"类问题。** 它只展示 132 条
   进程引用中的五条，且从早期行开始；位于第 683 行的最终启动不在
   该样本内。对本工作流而言，必须抓取完整 JSON。对于已知的精确进程
   问题，可直接跳过 summary 步骤。
2. **记录级输出会带来无关的负载。** 两条支撑结果行分别为 9,154 与
   7,202 字节。尽管调查关注的是包装器状态与关联，原始行展开仍包含
   它们的完整输出负载。
3. **分页放大了调用次数与校验读取。** 默认分页对八行需要 11 次调用。
   一项单独标注、调查之后的检查，用既有的 `--max-bytes 16384` 选项
   在八次调用内返回了同样的八条记录。完整报告加上那些页面使用了九次
   CLI 调用与 68,188 字节输出，且未改变产品。它仍会重读/校验快照。
4. **选择仍是调用方的工作。** AgentLRay 计算进程链接，但调用方仍需
   选择最新的合格进程并拼装其证据链。CLI 尚不提供有边界的、面向进程的
   查询/结果。

这些都是具体的工作流观测值，而不是授权再构建一层抽象，或放松
隐私/身份校验。在收集可比较的调查时，请保留既有的手动 CLI 工作流。
一个"有边界的、面向进程的查询"只有在考虑如何保留源证据、模糊性与
范围之后，才是一个候选改进；本轮并未加入此类功能。

## 这验证了什么

在该真实快照上，工具成功提供了可复用的进程关联与可验证的源码链接，
而无需调查者编写平台专属的连接器。一个自定义原始解析器也能得出相同
结论。证据支撑的是**一个可用的取证能力**，而不是对所有日志工具的
优越性、测量到的开发者生产力，或任何采用主张。

此处不发布任何原始源码路径、进程 ID、命令、用户文本或输出。行号与
聚合活动并不保证匿名。详细的本地收据仍位于被忽略的
`output/session-forensics/` 之下：`manifest.json`、`audit.cjs`、
`results.json`、`crosscheck.json`、`large-page-check.json` 以及私有的
快照/报告。本地驱动支持 `selftest`、`freeze` 与 `run`；freeze/results
拒绝覆盖。公开读者可对自己的日志应用该工作流，但无法从仓库复现这份
私有样本。
